No confiamos en nuestras propias apps de prueba: usamos los tests de otros builders tal como los publican. Cada caso arma la imagen con Acropolis, la corre con `docker run` y chequea la salida o un request HTTP, con los mismos timeouts que el original. Resultados a la v0.3.1:

## Qué encontraron [#what-they-found]

Estas suites encontraron bugs que nuestras propias apps nunca habrían mostrado: yarn v1 instalando binarios para todas las plataformas (177 MB de `sharp` para darwin, windows y arm en una imagen linux), `node_modules` de miembros de workspaces de pnpm que no llegaban a la imagen, Next 15 necesitando `typescript` en runtime para leer `next.config.ts`, parches de `patchedDependencies` que no se aplicaban, hardlinks duplicados que inflaban las capas, Go sin `go.mod` y Java con un Gradle viejo. Después vinieron otros: miembros de workspaces de yarn berry sin `node_modules` en la imagen, apps sin lockfile que compartían entre sí la capa cacheada de `node_modules` y terminaban con los builds musl de `@next/swc` y `sharp` (41 MB más por imagen de Next), `node-gyp` faltante cuando otro plan había instalado el mismo Node sin npm, y capas con una ruta escrita dos veces, que `docker pull` rechaza en overlay2.

Las imágenes se prueban con `docker pull` desde un registry local, y en cada capa de cada imagen (las capas base también) se chequea que no haya rutas duplicadas. Con `E2E_OCI=1`, el harness además carga el tar de `--oci` con `docker load`, que es como las consume Olimpia.
